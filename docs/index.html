Start

What changes on Duo

iPhone Duo is still an iPhone, so iOS patterns still apply. What's new is that your app can appear at many more sizes, with toolbars that move to the side and a fold through the middle of the large display.

Outer display

Compact width

Behaves like other iPhones. Portrait is compact width and regular height, and landscape is compact in both. Toolbars and tab bars sit on the side. The front camera is in the corner and always visible.

Inner display

Regular width and height

Room for sidebars and two panes. Supported orientations are ignored for layout, so the app scales here, including in Split View. The camera is under the display and visible only while in use.

Hinge

Six poses

Closed, folded like a book, folded like a laptop, tent, and flat (wide or tall). When partially open, the fold divides the inner display in two.

Transitions

Resize, not reconnect

Opening or closing the phone is a size and trait change. State, keyboard, scroll position, video and camera sessions all survive.

How your build behaves

Built withOn iPhone Duo
iOS 26 SDK or earlierCompatibility mode. Centred with empty space when open, and squeezed left of the status bar and camera when closed.
iOS 27 SDKFills most of the inner display but still avoids the status bar edge.
iOS 27.1 SDKFull edge to edge, with toolbars and tab bars moved to a vertical bar on the side. Check that your content adapts to the side bar before shipping.

Porting in seven steps

Steps 1 to 3 are the port itself, and every app needs them. Steps 4 to 7 adopt Duo features where they help your app. The skill follows this same order.

  1. Audit the codebase Port

    Find screen-based sizing, orientation and device checks, custom bars and camera direction assumptions. Search commands

  2. Fix resizing Port

    Size from your view or scene, not the screen. Choose layouts by size class. Handle each safe-area edge on its own. Patterns

  3. Move bars to the side Port

    Use system bars, give every item an icon and a title, and set overflow priority. Guide

  4. Lay out around the fold Duo

    Two related panes go in an ArrangementView. API

  5. Keep custom UI clear of reserved regions Duo

    Move floating controls away from the fold and the cameras. API

  6. Add hinge interactions Duo

    Use the hinge angle for effects and gestures, never for layout. API

  7. Handle cameras and the outer display Duo

    Pick the camera by the direction it faces, and show content to the person being filmed. API

Safe areas on Duo are often asymmetric, because a side bar takes one edge only. Handle each side on its own:

UIKit
// Wrong: assumes opposite insets are equal
let width = view.bounds.width - view.safeAreaInsets.left * 2

// Right: handles each side independently
let width = view.bounds.inset(by: view.safeAreaInsets).width

Prefer system containers, because they adapt to the fold and cameras for you. NavigationSplitView and UISplitViewController collapse when closed and tile when open. Tabs can become a sidebar on the inner display:

Guide

Side toolbars

On the outer display, and on the inner display in landscape, the navigation bar, toolbar and tab bar stack into one vertical bar on the side. Only bars owned by navigation containers move there. A standalone UIToolbar or custom SwiftUI bar stays where it is.

Order

Back or Close goes at the top, then prominent actions such as Done, then the rest in their usual groups.

Icon and title

Give every item both. The side bar shows the icon and the overflow menu shows both. Title-only and custom-view items never move to the side.

Overflow

Items overflow from the bottom up. Raise frequent actions and badged items with visibilityPriority. Use the system overflow menu, not your own ellipsis.

Compression

Navigation apps keep the tab bar, which is the default. Task apps keep the toolbar with .prefersToolbarItems.

NavigationStack {
    EditorView()
        .toolbar {
            ToolbarItem(placement: .cancellationAction) {
                Button("Close", systemImage: "xmark") { dismiss() }
            }
            ToolbarItem(placement: .topBarPinnedTrailing) {
                Button("Done", systemImage: "checkmark") { save() }
            }
            ToolbarItem {
                Button("Share", systemImage: "square.and.arrow.up") { share() }
            }
            .visibilityPriority(.high)
            ToolbarOverflowMenu {
                Button("Duplicate", systemImage: "plus.square.on.square") { duplicate() }
                Button("Export PDF", systemImage: "doc") { export() }
            }
        }
}
navigationItem.leadingItemGroups = [UIBarButtonItemGroup(barButtonItems: [closeItem], representativeItem: nil)]
navigationItem.pinnedTrailingGroup = UIBarButtonItemGroup(barButtonItems: [doneItem], representativeItem: nil)

shareItem.visibilityPriority = .high
navigationItem.additionalOverflowItems = UIDeferredMenuElement({ provider in
    provider(self.persistentOverflowItems())
})

Sheets on the outer display get side bars. On the inner display, leading or centred sheets keep horizontal bars and trailing sheets get side bars. Set placement with presentationPlacement(_:) or UISheetPresentationController.preferredPlacement.

Read the hinge's status and its live angle. Use this for interactions and effects only. For layout, use arrangement views and reserved regions. The update rate and precision are system policy, so don't depend on either.

Example
override func viewDidLoad() {
    super.viewDidLoad()

    let interaction = UIHingeInteraction { [weak self] _, update in
        guard let self else { return }
        // nil means this view left a hierarchy that provides hinge updates

Reserved regions

Hardware areas your content should avoid. System containers already handle them. Query them for custom overlays, floating controls, custom bars and explicit-frame layouts. Touches over a reserved region may not register.

.division

The fold

Active when the phone is partially open. When fully open it's inactive with zero width. Keep each view entirely on one side.

.occlusion

Cameras and window controls

The outer camera is always active and grows into the Dynamic Island. The inner camera is active only while in use.

Camera direction

Duo has a front camera above each display. When the phone opens, closes or turns around, the camera that faces the user changes. AVCaptureDevice.position still reports where a camera sits, not which way it points.

Device typeWhat it isLimits
Front discovery with .builtInWideAngleCamera / .builtInUltraWideCameraThe virtual front camera. It follows your app between displays automatically, and existing apps keep working.1080p, 60 fps, no depth
.builtInOuterUltraWideCameraThe physical outer front cameraUp to 4K, 120 fps
.builtInInnerUltraWideCameraThe under-display inner camera1080p, up to 60 fps

AVCaptureDeviceDirectionCoordinator

AVKitiOS 27.1+@MainActor

Give it your preview view, every built-in camera you capture from (rear ones too, but not the virtual front camera) and a change handler. The handler receives an AVCaptureDeviceDirectionMap with forwardFacingDeviceDescriptors and backwardFacingDeviceDescriptors. Keep a strong reference, and create one coordinator per preview view.

Switch to whichever camera faces the user
@MainActor
final class DirectionObserver {
    private let captureService: CaptureService      // your actor
    private var coordinator: AVCaptureDeviceDirectionCoordinator?
    private var active: AVCaptureDeviceDescriptor?

    init(captureService: CaptureService) { self.captureService = captureService }

    func startObserving(previewView: UIView) {
        coordinator = AVCaptureDeviceDirectionCoordinator(
            view: previewView,
            deviceTypes: [.builtInOuterUltraWideCamera,
                          .builtInInnerUltraWideCamera,
                          .builtInDualWideCamera]
        ) { [weak self] map in self?.directionsChanged(map) }
    }

    private func directionsChanged(_ map: AVCaptureDeviceDirectionMap) {
        let forward = map.forwardFacingDeviceDescriptors
        if let active, forward.contains(active) { return }
        guard let next = forward.first else { return }
        active = next
        // Never call AVFoundation here; hand the Sendable descriptor to your actor.
        Task { try await captureService.selectCamera(with: next) }
    }
}
In your capture actor
func selectCamera(with descriptor: AVCaptureDeviceDescriptor) throws {
    guard let device = AVCaptureDevice(uniqueID: descriptor.uniqueID) else { return }
    let input = try AVCaptureDeviceInput(device: device)

    session.beginConfiguration()
    defer { session.commitConfiguration() }
    if let activeInput { session.removeInput(activeInput) }
    guard session.canAddInput(input) else {
        if let activeInput { session.addInput(activeInput) }
        return
    }
    session.addInput(input)
    activeInput = input
}

Scene accessories

The only way to put content on the outer display while your app runs on the inner one. CameraCaptureAccessory shows when the phone is open, your app is in the foreground and full screen on the inner display, and a capture session is running. A typical use is a teleprompter for the person being filmed. The system can withdraw it at any time, so it must never be the only way to do something.

Example

Fold to scrub

Scrub through a timelapse by folding the phone. Two habits make hinge gestures feel right. First, respond only while the phone is .partiallyOpen. Second, work from the change in angle since the gesture started, not the absolute angle, because Apple doesn't document the reported range. Here every 2° moves one frame.

SwiftUI
struct TimelapseViewer: View {
    let frameNames: [String]
    @State private var frameIndex = 0
    @State private var anchor: (angle: Angle, frame: Int)?
    @State private var foldToScrub = true

    var body: some View {
        VStack {
            Image(frameNames[frameIndex]).resizable().scaledToFit()
            Slider(value: Binding(get: { Double(frameIndex) },
                                  set: { frameIndex = Int($0.rounded()) }),
                   in: 0...Double(max(frameNames.count - 1, 1)))   // non-hinge path
            Toggle("Fold to scrub", isOn: $foldToScrub)
        }
        .onHingeChange(isEnabled: foldToScrub) { old, new in
            guard let hinge = new.hinge, hinge.status == .partiallyOpen else {
                anchor = nil
                return
            }
            if old.hinge?.status != .partiallyOpen || anchor == nil {
                anchor = (hinge.angle, frameIndex)
            }
            guard let anchor else { return }
            let moved = hinge.angle.degrees - anchor.angle.degrees
            let target = anchor.frame + Int((moved / 2).rounded())
            frameIndex = min(max(target, 0), frameNames.count - 1)
        }
    }
}
  • Always provide a button or slider that does the same thing, for other iPhones, for accessibility, and for people who don't want to fold.
  • Smooth the motion with an animation or spring, and ignore changes under about 1°.

Older iOS wrapper

If your deployment target is below iOS 27.1, the hinge types can't appear in your own signatures. Wrap them in a plain value so call sites stay clean on every OS.

SwiftUI
struct HingeReading: Equatable {
    enum Status { case closed, partiallyOpen, fullyOpen, unknown }
    var degrees: Double
    var status: Status
}

extension View {
    /// Calls `action` with the hinge reading, or nil without a hinge or before iOS 27.1.
    @ViewBuilder
    func onHingeReading(isEnabled: Bool = true,
                        perform action: @escaping (HingeReading?) -> Void) -> some View {
        if #available(iOS 27.1, *) {
            self.onHingeChange(isEnabled: isEnabled) { _, new in
                action(new.hinge.map { hinge in
                    let status: HingeReading.Status
                    switch hinge.status {
                    case .closed: status = .closed
                    case .partiallyOpen: status = .partiallyOpen
                    case .fullyOpen: status = .fullyOpen
                    default: status = .unknown
                    }
                    return HingeReading(degrees: hinge.angle.degrees, status: status)
                })
            }
        } else {
            self.onAppear { action(nil) }
        }
    }
}

Split custom content at the fold

Use this when ArrangementView doesn't fit, such as a custom canvas or a game board. It works out which way the fold runs and leaves the fold itself empty. This example is adapted from Apple's ReservedRegion documentation.

SwiftUI
struct SplitContent: View {
    var body: some View {
        GeometryReader { proxy in
            if let division = proxy.reservedRegions(kind: .division).first {
                let f = division.frame
                if f.height > f.width {
                    // Book fold: the fold runs vertically, so panes sit side by side
                    HStack(spacing: 0) {
                        FirstPane().frame(width: f.minX)
                        Color.clear.frame(width: f.width)
                        SecondPane().frame(width: proxy.size.width - f.maxX)
                    }
                } else {
                    // Laptop fold: the fold runs horizontally, so panes stack
                    VStack(spacing: 0) {
                        FirstPane().frame(height: f.minY)
                        Color.clear.frame(height: f.height)
                        SecondPane().frame(height: proxy.size.height - f.maxY)
                    }
                }
            } else {
                FirstPane()
            }
        }
    }
}
In grids, prefer an even number of columns whenever a division exists. Query with .includeInactive to decide that before the user folds.

Selfie mirroring

Base mirroring on the direction map, not on position. When a rear camera faces the user, mirror it. When a front camera faces away, don't. Turn off automatic mirroring first, or setting isVideoMirrored throws an exception.

AVFoundation
private func applyVideoMirroring(from map: AVCaptureDeviceDirectionMap) {
    guard let connection = previewConnection, connection.isVideoMirroringSupported else { return }

    let id = activeDevice.uniqueID
    let facingForward  = map.forwardFacingDeviceDescriptors.contains { $0.uniqueID == id }
    let facingBackward = map.backwardFacingDeviceDescriptors.contains { $0.uniqueID == id }
    let isFrontCamera  = activeDevice.position == .front

    // Take over only when where the camera sits and where it points disagree
    let needsOverride = (facingForward && !isFrontCamera) || (facingBackward && isFrontCamera)
    guard needsOverride else { return }

    connection.automaticallyAdjustsVideoMirroring = false   // must come first
    connection.isVideoMirrored = facingForward
}

Call it on every new map and again after swapping inputs, because a new input creates a new connection. Also create a new AVCaptureDevice.RotationCoordinator for each camera.

App Store

  • Build with the iOS 27.1 SDK. From April 2027, uploads require the iOS 27 SDK or later.
  • Upload iPhone Duo screenshots in App Store Connect. That alone adds the "Made for iPhone Duo" badge to your product page.
  • Preview your assets in App Store Connect. When you nominate the app for featuring, say it supports all poses.
Ship

Patterns to avoid

  • A custom layout for each pose. Use compact width for the outer display and regular width for the inner one.
  • Choosing a layout from the hinge angle, or relying on its update rate or absolute values.
  • Text-only or custom-view toolbar items you expect to move to the side, or your own ellipsis menu.
  • Overriding where the side bar goes without a strong reason.
  • Content or controls sitting in the fold.
  • Treating a camera's position as the direction it faces.
  • Essential UI that exists only in a scene accessory.
  • UIScreen.main, orientation checks and idiom checks for layout.
